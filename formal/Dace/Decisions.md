# Semantic decision register

Every place where DaCe's documented intent, its code generator, and a clean
mathematical model disagree (or where behavior is undefined) is recorded here
together with the model chosen for the Lean formalization and the evidence.
Entries are referenced from the Lean sources as `Decisions.md#<id>`.

Status: **living document**, started 2026-10-16. Line references are to the
DaCe sources at the time of writing.

| Id | Topic | DaCe evidence | Model chosen |

| D1 | Integer arithmetic | Codegen emits native C ints (default `int32`, `dace/symbolic.py:26`), wrapping and truncating `/`, `%`; SymPy expressions use exact rationals (`1/2*N`) | Idealized `ℤ` with exact rationals `ℚ` for symbolic division; `int_floor` = floor division (Python `//`), `int_ceil` = ceiling division, `Mod` = Python modulo (sign of divisor). Overflow and C truncation are out of scope (assumption; codegen's `int_floor` truncates for negative operands). |
| D2 | Multiple true interstate conditions | Doc: undefined (`doc/sdfg/ir.rst:151-152`); codegen takes the first true edge in out-edge order (`dace/codegen/control_flow.py:304-328`) | Undefined behavior (`ambiguousTransition`, owner 2026-10-20): several true out-edges have no meaning. | D3 | Map schedules | Maps are parallel scopes (`doc/sdfg/ir.rst:446-471`); `Sequential` lowers to ordered `for` loops (`cpu.py:2132-2148`) | `schedule` and the other map hints (`unroll`, `collapse`) are semantically inert and not imported (nor is any descriptor's `storage`): every map is a parallel scope; iteration logs are merged, conflicts are an `error race`. If several iterations fail, any one's error is an outcome, independent of the order of the iteration points (owner 2026-10-27; `IterExec.tailErr` needs no successful earlier iteration). Sequential execution is a refinement. |

Cells hold `Val.undef` while uninitialized. Every element read of an `undef` cell is undefined behavior (`uninitRead`): tasklet and library inputs, copies (both ends of a copy are element accesses; copying an uninitialized element is undefined, not a transfer of indeterminacy), and data reads in expressions (interstate conditions and assignments, dynamic ranges, which fail as `undefinedExpr`). Writes only store defined values. A WCR contribution onto an `undef` cell leaves it `undef` (`WcrSem.Lawful.undef_absorb`; the concrete operators return `undef` for an `undef` old value), so the indeterminate old value makes every later read of the cell undefined; failing at the contribution itself would make a WCR depend on the definedness of its target and break the independence of parallel contributions (`Foot`). A program that accumulates into an uninitialized transient and never reads it is therefore defined in the model (C++ already reads the indeterminate value). *Allocating* a container fills all its cells with `undef` and empties its queues (a fresh stream is empty, D5). Allocation points (SDFG semantics), on memory names (`Ctx.cname`): (1) **program start**: every location except those of the top-level non-transient containers (the arguments) and of the top-level `External` transients is uninitialized; this covers `Persistent` and `Global` transients, which are never allocated again (nested SDFGs own no `Persistent`/`External` transients, D63). (2) **SDFG invocation** (a nested call; the top level is covered by (1)): the SDFG's transients with lifetime `SDFG`, and `Scope`/`State` transients that are shared (mentioned in several states, or by an interstate edge, a loop's init/condition/update or a branch condition, `Region.countMentions`). (3) **State execution**: the unshared `Scope`/`State` transients mentioned in the state. (4) **Map iteration / consume task**: the private transients of the scope (D39), on the iteration's local memory. Allocations (2) and (4) are on fresh locations (`Mem.allocAll`); allocation (3) leaves the queues of containers that are no streams unchanged (they are never used), so that a state's allocation only makes its memory less initialized (`allocate_left`). Deallocation is not modeled: every later use of a container is preceded by its next allocation, so it is unobservable. Two calls of a nested SDFG (two nodes, or one node twice) have separate per-call transients; their log entries stay inside the call (D34), while `Global` transients of a nested SDFG are logged like any container, so parallel calls writing them race (hoisted `Persistent` ones are outer containers reached through connectors, so the same writes race on the nested node's edges). Schedule trees have no states or calls: the tree semantics allocates at (1) (arguments and `External` transients defined) and (4) (D54) only, so a tree is never stricter than the SDFG it was converted from, which is what tree-refines-SDFG claims need. Not modeled: allocation hoisting by storage type (the model is stricter than such code). |
