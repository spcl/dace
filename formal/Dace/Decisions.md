# Semantic decision register

Every place where DaCe's documented intent, its code generator, and a clean
mathematical model disagree (or where behavior is undefined) is recorded here
together with the model chosen for the Lean formalization and the evidence.
Entries are referenced from the Lean sources as `Decisions.md#<id>`.

Status: **living document**, started 2026-10-16. Line references are to the
DaCe sources at the time of writing.

| Id | Topic | DaCe evidence | Model chosen |
|----|-------|---------------|--------------|
| D1 | Integer arithmetic | Codegen emits native C ints (default `int32`, `dace/symbolic.py:26`), wrapping and truncating `/`, `%`; SymPy expressions use exact rationals (`1/2*N`) | Idealized `ℤ` with exact rationals `ℚ` for symbolic division; `int_floor` = floor division (Python `//`), `int_ceil` = ceiling division, `Mod` = Python modulo (sign of divisor). Overflow and C truncation are out of scope (assumption; codegen's `int_floor` truncates for negative operands). |
| D2 | Multiple true interstate conditions | Doc: undefined (`doc/sdfg/ir.rst:151-152`); codegen takes the first true edge in out-edge order (`dace/codegen/control_flow.py:304-328`) | Nondeterministic choice among true edges. Codegen order is a refinement. |
| D3 | Map schedules | Maps are parallel scopes (`doc/sdfg/ir.rst:446-471`); `Sequential` lowers to ordered `for` loops (`cpu.py:2132-2148`) | `schedule` is semantically inert: every map is a parallel scope; iteration logs are merged, conflicts are an `error race`. Sequential execution is a refinement. |
| D4 | Concurrent components in a state | Parallel only under `openmp_sections` (`framecode.py:558-574`), else emitted sequentially | Components run in parallel (permission); each component in some topological order; logs merged. |
| D5 | Stream `buffer_size` | Initial queue capacity only; push never blocks or drops; pop blocks on empty (`stream.h:81-124`) | `buffer_size` advisory; `push` appends; `pop` on empty = `error stuckPop`. |
| D6 | WCR on streams | Doc forbids (`ir.rst:433-434`); not validated, silently ignored by codegen | Ill-formed (rejected by WF). |
| D7 | Stream-to-stream copy | `NotImplementedError` (`cpu.py:953-955`) | Ill-formed. |
| D8 | Consume early stop | Remaining elements stay in the queue; never-true condition on an empty stream spins | Remaining elements stay; divergence is the absence of an outcome. |
| D9 | `other_subset = None` on copies | Full range of the other array (`cpp.py:185-188`) | Normalized at import to the full range. |
| D10 | Copy element order | Row-major over the squeezed copy shape (`copy.h`) | Elementwise over `zip (points src) (points dst)` in lexicographic order. |
| D11 | References | May be set several times in a state (no validation); read before set rejected by validation | Last `set` in dataflow order wins; read of an unset reference = `error unsetRef`. |
| D12 | Dynamic map inputs | Scalars only in practice (`cpu.py:2021-2028`) | Scalar symbol bound before the iteration space is evaluated. |
| D13 | Unassigned tasklet outputs | Static scalar outputs are written back unconditionally (`cpu.py:1212-1258`); dynamic outputs are may-writes | WF requires static outputs to be written; dynamic outputs are `Option`. |
| D14 | Stream connector reads | Each read of a dynamic stream input pops (`cpp.py:1328`) | Modeled as such in the executable tasklet subset; opaque tasklets declare pop counts. |
| D15 | Nested SDFG descriptor `offset` | Excluded from `is_equivalent` (`dace/sdfg/dealias.py:1240-1250`) | Ignored; inner memlets address the outer container with identical indices. |
| D16 | Legacy (windowed) nested SDFGs | Converted by `convert_legacy_nested_sdfgs` (`dealias.py:1469`); not inlined otherwise | Rejected by the importer; only the no-view/no-squeeze contract is modeled. |
| D17 | View edge ambiguity | `get_view_edge` falls back to the input edge with a warning (`dace/sdfg/utils.py:1223-1225`) | Same resolution order, reproduced in WF. |
| D18 | `nosync` | GPU-only effect (`cuda.py:1799`) | Ignored. |
| D19 | `StateBoundaryNode` | Conversion artifact of tree→SDFG | No stree syntax; appears only in the correspondence relation. |
| D20 | Stree sibling order | SDFG→tree serializes a state by one topological order | Sibling order is one valid schedule; the correspondence accepts any topological order. |
| D21 | Structures / ContainerArrays | Member access `a.b` lowered to `a->b` | Full syntax and the generic `Loc` memory model; no theorems in this phase. |
| D22 | Symbolic expression parsing | DaCe stores sympy expressions as Python-syntax strings; serialized symbols carry a `$` prefix; `SymExpr(exact, approx)` pairs an expression with an over-approximation | Parsed by `Core/Parse` (both `$`-prefixed and bare symbols); `SymExpr` becomes `Expr.approx` and evaluates as its exact part; unknown function calls become opaque `app` nodes. |
| D23 | Floating point | Tasklets and symbolic expressions may use floats | Floats are an abstract sort interpreted by `Interp`; no IEEE semantics. |
| D24 | Custom WCR lambdas | Commutativity/associativity checked symbolically, may be indeterminate (`dace/frontend/operations.py:201-250`) | Assumed commutative and associative (hypothesis `WcrSem.Lawful` of the semantics). |
| D25 | Parallel pushes to one stream | Concurrent producers enqueue in a nondeterministic interleaving | Logs record pushes per execution; `merge` appends them in list order (one admissible interleaving). Pops require exclusive access. |
| D26 | WCR lambda representation | Stored as source text `lambda a, b: body`; built-ins detected by `detect_reduction_type` | Parsed once into `WcrOp.custom a b body` with structural detection of built-ins; the interpreter evaluates custom bodies by binding `a := old`, `b := new`. An undefined evaluation degrades to `new`. |
| D27 | Empty memlets | `Memlet()` with no data; codegen emits nothing, only orders the endpoints (`cpu.py:844-846`, `concurrent_subgraphs`) | A distinct edge payload `EdgeData.dep`: a happens-before edge that also locks a node into a scope; carries no data. |
| D28 | Executable Python tasklet subset | Tasklet code is Python expression statements (`unparse_tasklet`, `cpp.py`); dynamic stream reads become `.pop()` and stream writes `.push(...)` (`cpp.py:1236,1328`); scalar outputs are written back as `conn = …` (`cpp.py:1238`) | `Core/PyTasklet` runs a statement sequence (`target = e`, augmented `target OP= e` reading the target first, `pass`, `conn.push/append(e)`, `conn.pop()`) over locals + connector bindings; expressions reuse `Expr.eval` with a math-aware `app` (`math.*`, `min/max/abs`, `int()/float()` and `dace.<dtype>()` casts). Each stream input read pops one value (counted in `pops`); a plain name that is an output connector is a scalar write (last wins), a subscript on an output connector an array write, `conn.push(e)` a stream push. Assigned values are coerced to the connector's declared `Dtype` (float → `Val.float`, int → `Val.int` truncated toward zero, bool → `Val.bool`). Compound statements (`if`/`for`/…) and non-Python languages are unsupported (`none`); conditional *expressions* `a if c else b` are supported. The parser/evaluator are executable (`partial`), not reasoned about. |
| D29 | Leaf endpoints | Codegen resolves copies and connector accesses through `memlet_path` and names containers by the access nodes at the path ends (`cpu.py:2376-2398`, `cpu.py:1185-1258`); `Memlet.data` may name either side | The endpoints of a leaf edge are structural: its access node, the access node at the end of its memlet path through scope nodes, the producing code node (values kept in `St.vals` keyed by `(node, out-connector)`), or the consume chunk. `Memlet.data` is not used to identify containers; the normalized `srcSubset`/`dstSubset` are the subsets of the two sides, a still-missing one is the full range. |
| D30 | Where copies execute | `_generate_AccessNode` dispatches copies at the destination access node (`cpu.py:2376-2398`); exit nodes write back their in-edges | A copy executes when its destination node (access node or scope exit) executes; a code node reads its in-edges and writes its out-edges when it executes. Scope exit nodes are ordinary body nodes whose only effect is these copies. |
| D31 | View binding time | Views are bound at the start of their scope (`framecode.py:630`; `allocate_arrays_in_scope` at state begin and at map entry, `cpu.py:2153`); the schedule tree emits `ViewNode`s first in each scope (`sdfg_to_tree.py:442-459`) | View aliases are bound in the prologue of every sequential execution (state component, map iteration, consume task) for the view access nodes directly in that scope, in node order (`bindViews`); the view edge itself is not a copy. Bindings inside a map are private to the iteration (D39). |
| D32 | Reference `set` | `is_refset` assigns the pointer at the producing edge (`cpu.py:1210-1251`) | Bound when the reference access node executes (dataflow order, D11); base = access node at the start of the edge's memlet path, offset = lower corner of the source subset. |
| D33 | Data in symbolic expressions | Interstate conditions/assignments may read scalars by name and array elements by subscript (`doc/sdfg/ir.rst`, `cpp.py:unparse_interstate_edge`) | A bare name denotes a scalar container when no symbol of that name is bound; subscripts read elements through `Ctx.loc`. Such reads are not logged (not race-checked). |
| D34 | Nested SDFG symbols and connectors | Codegen passes `symbol_mapping` values and the outer memlet pointers (`cpu.py:1924-1941`, `generate_nsdfg_arguments`); unmapped inner symbols keep the outer value | Inner valuation: mapped symbols evaluated in the outer context, others inherited, inner constants added; symbols never flow out. Connectors alias the outer root container with offset 0 (D15); scalar values on code→nested and nested→code edges are copied by value. Log entries on connector names and inner transients are dropped from the outer log. |
| D35 | Interstate edge evaluation | Codegen tests conditions in order (`control_flow.py:295-328`) | All out-edge conditions are evaluated (an undefined one is an error), one true edge is chosen (D2); assignments are simultaneous with right-hand sides in the old valuation. |
| D36 | Loop lowering variants | `LoopRegion.inline` (`state.py:3609-3747`) always goes body → latch (update) → guard (condition) and ignores `update_before_condition`; codegen honours it (`control_flow.py:139-158`: `do {body; update} while (cond)` vs `while(1) {body; if (!cond) break; update}`); a C `continue` in `do`-`while` skips the emitted update | Follows codegen for inverted loops: `updateBeforeCond` ⇒ body, update, condition; otherwise body, condition, update. `continue` proceeds to the loop tail as in `inline`. Non-inverted loops: condition, body, update. `break` exits normally, `return` propagates. |
| D37 | Reduce without identity | `ExpandReducePure` has no initialization state and accumulates with WCR onto the existing output (`reduce.py:98-115,133-138`); `ExpandReduceOpenMP` writes the identity only when given (`reduce.py:363-365`) and uses an OpenMP `reduction` clause, which combines with the original value | With `identity`: fold from the identity, written plainly (or through the out-memlet's WCR); without: the fold of each group is contributed to the existing output through the reduce operator. Input points are grouped by their non-reduced coordinates, in output order. |
| D38 | Consume scope | PEs are threads popping up to `chunksize` elements and running the body until the quiescence condition fails (`stream.h:337-430`); the chunk is a scope-local scalar/array (`cpu.py:2270-2307`) | Tasks are sequentialized in the relation: task k pops from the queue left by tasks < k, the PE index is chosen nondeterministically in `[0, num_pes)`, the chunk is a task-private pseudo-container. Task logs are merged like map iterations with the consumed stream's effects removed; the stream ends with the remaining elements followed by the bodies' pushes in task order (`exclusive`). Default condition = non-empty; an explicit condition that holds on an empty queue yields no derivation (D8). |
| D39 | Private transients of a scope | Scope-lifetime transients are allocated per iteration (`framecode.py:determine_allocation_lifetime`) | A transient all of whose access nodes (over every state of the SDFG) lie inside the scope is private: its entries are dropped from the iteration/task log, so iterations do not race on it. Views are transient, hence per-iteration view bindings are private. |
| D40 | Tasklet connector shapes | Scalar vs pointer connectors (`cpu.py:1206-1212`, `memlet_definition`) | Single-point subset ⇒ scalar; multi-point ⇒ pointer connector addressed relative to the lower corner (first enumerated point), whole footprint logged as read; a scalar output to a multi-point subset is malformed. Static outputs the interpretation does not assign are not written. |
| D41 | Consume condition | Stored as a `CodeProperty` | Parsed at import into `Expr` (`ConsumeNode.condition : Option Expr`) like interstate conditions, so the semantics never calls the (partial) parser. |
| D42 | Sources of dynamic inputs | `dynamic_map_inputs` (`cpu.py:2021-2028`); stream reads pop (`cpp.py:1328`) | A single element of a container, one popped element of a stream, or the value on a code edge; an absent code value leaves the symbol unbound. |
| D43 | Scope body order | Code is generated in a topological order of `scope_children` (`cpu.py:generate_scope`) | A scope body (and a state component) executes its direct children in the restriction of a topological order of *all* nodes of the scope, so that paths through nested scopes order their endpoints; the order is nondeterministic (D20). The interpreter uses Kahn's algorithm and re-checks `isTopologicalOrder` on the result (the relation's premise); when the check fails (cyclic body, duplicate node ids, self-loop edges — all excluded by WF) there is no derivation and the interpreter returns `none`. |
| D44 | Reads after own WCR | In `map { A → tasklet --wcr--> C[i] → tasklet }` the second tasklet performs an ordinary load of `C[i]` and observes an arbitrary partially reduced value when other iterations also contribute (undefined in practice; DaCe does not detect it) | `Log.seq` keeps such reads in the log (only reads after an own *plain* write are internal), so `merge` reports `race` on that location whenever another execution writes or contributes to it. With a single contributor per location the read is well defined and sees the pre-scope value plus the own contribution. |
| D45 | Start block of a control-flow region | `start_block` is the unique source block (in-degree 0) when there is exactly one, else the explicitly stored `_start_block` index, else an error (`dace/sdfg/state.py:3459-3476`); serialized files usually carry `start_block: null` | Resolved once at import into the plain field `Region.start` by the same rule (`Dace/SDFG/Json.lean`); the semantics only reads the field. A region with several sources and no explicit index is rejected by the importer. |
| D46 | Symbols in tasklet code | Tasklet bodies may name SDFG symbols, map parameters and dynamic scope inputs directly (`__out = count`, `a * i`); the generated code places the body in a scope where these are C variables (`cpu.py:unparse_tasklet`, symbols as function arguments and loop variables) | `TaskletSem` receives the current valuation `ρ` in addition to the connector bindings; the executable subset resolves a bare name as local, then output scalar, then input connector, then symbol (connectors shadow symbols; an unbound name is undefined). |
| D47 | Dynamic WCR outputs are fetch-and-add | For a *dynamic* (or stream) WCR memlet the assignment `out = v` in a tasklet is rewritten to `out = reduce_atomic(ptr, v)` (`cpp.py:1214-1228`) and `reduce_atomic` returns the pre-update value (`reduction.h:175-180`, `omp atomic capture`), so the tasklet may keep using `out` as the old value (unique-index allocation, lock-free queues). Static WCR outputs discard the return value. | Out of scope for now: a code node with a dynamic WCR out-memlet is `malformed` ("fetch-and-add not modeled") instead of silently returning the assigned value. Planned extension: `TaskletSem` as an effect tree with `fetchWcr`, plus a per-location linearization of contributions in `merge` (the observed old value is a prefix fold under a chosen permutation; the final value stays the commutative fold). |
| D48 | Schedule tree node catalog | `treenodes.py` defines 25 concrete classes; `serialize.py` stores dataclass fields by name, loop metadata as the `LoopRegion` fields, `global_code`/`init_code`/`exit_code` alongside. `AssignNode` is `name` + `value` only (`treenodes.py:491-508`; its reads are the subscripts/scalars of `value`, as `InterstateEdge.get_read_memlets` computed them from the former redundant `edge` field); `serialize.py:321` ignores an `"edge"` key of older files | One `SNode` constructor per class except `ScheduleTreeRoot` (the structure `STree`) and `StateBoundaryNode` (rejected by the importer, D19). The four loop classes are separate constructors over one `LoopMeta`; `LoopMeta.variant` is `loop_variant`. Conditions, assignment values and loop statements keep their source text next to the parsed `Expr` (`PyExpr`, `PyAssign`) for `as_string`. `SNode.assign` has a name and a `PyExpr` only. `global_code`/`init_code`/`exit_code` (codegen hooks) and `callback_mapping` values carry no semantics and are ignored or kept for the record. |
| D49 | Sequential tree assignments vs simultaneous edge assignments | An interstate edge assigns all its symbols simultaneously (D35); `sdfg_to_tree._isedge_schedule_tree` splits an edge into one `AssignNode` per symbol in dictionary order, and `tree_to_sdfg._insert_and_split_assignments` re-splits a run of pending assignments into separate transitions whenever one reads a symbol another assigns | `AssignNode`s execute sequentially (`applyAssigns` with one pair). Both views agree because SDFG validation rejects an edge whose assignment reads a symbol assigned on the same edge, so the simultaneous and the sequential evaluation coincide on well-formed inputs. |
| D50 | Dynamic scope inputs in trees | `DynScopeCopyNode`s directly precede the scope they feed (`sdfg_to_tree._state_schedule_tree`); `tree_to_sdfg.visit_DynScopeCopyNode` queues them in `_dynamic_scope_inputs` and `_visit_dataflow_scope` connects the queue to the next entry node; the consumed stream of a `ConsumeScope` is given as the `IN_stream` input; inside a consume scope `_read_source` provides the consumed stream through `OUT_stream` (the element) | The sibling-list relation carries `Pending`: symbol bindings (one element read, or one popped stream element, D42) and the `IN_stream` stream location (not popped). The next `MapScope`/`ConsumeScope` binds the symbols in its body valuation only (D12); pending inputs reaching any other node or the end of the list are `malformed`. Inside a consume body a memlet on the consumed stream denotes the chunk (`TCtx.consumed`), pushes to it are deferred as in D38. |
| D51 | Gotos and returns in trees | `GotoNode(None)` is a return (`treenodes.py`); `_bind_exits_to_label` turns the exit gotos of a flattened nested SDFG into forward gotos to a label appended to its scope; `tree_to_sdfg._find_label`/`_lower_forward_gotos` accept gotos to labels of enclosing scopes that follow the goto, `visit_GBlock` lowers labels of a general block to states (backward jumps allowed), and `visit_GotoNode` rejects exit gotos inside dataflow scopes and nested SDFGs | `TCtl` extends `Ctl` by `goto l`. `ret` ends the program (normal termination); `goto l` unwinds scopes until a sibling list resolves `l` (`resumeAt`: after a later sibling label anywhere, after any label of the list inside a `GBlock`) and resumes after the label with a fresh sibling context; a goto escaping the root, and any `brk`/`cont`/`ret`/`goto` leaving a map iteration or consume task, is `malformed`. WF rejects exit gotos inside dataflow scopes and gotos whose label is not visible without crossing a dataflow scope. |
| D52 | `if`/`elif`/`else` chains | `ElifScope`/`ElseScope` are siblings of their `IfScope`; `tree_to_sdfg._process_next_conditional_block` attaches them to the conditional block only when they immediately follow; `StateIfScope` is a conditional state transition | The sibling context carries `chain : Option Bool` (`some taken`): `IfScope` opens it, `ElifScope`/`ElseScope` run only when the chain is open and untaken, any other node (including `StateIfScope`, labels and dataflow scopes) closes it; an `elif`/`else` without an open chain is `malformed` (WF rejects it). |
| D53 | `CopyNode` direction | `tree_to_sdfg.visit_CopyNode` reads `memlet.data` and writes `target` with `other_subset` (full range when absent, cf. `_connect_output`); `sdfg_to_tree` normalizes the memlet to the outermost access node and names the innermost one as `target` | `execCopyT`: source = `memlet.data[memlet.subset]`, destination = `target[other_subset]` (full range when absent, D9), elementwise with WCR, stream endpoints as in `copyData` (D7, D10). Note: for a leaf edge from an inner access node *out* through a scope exit, `_prepare_schedule_tree_edges` names the inner node as `target` and normalizes the memlet to the outer one, which inverts the direction; the model follows `tree_to_sdfg` and the Python side should be reviewed. Update: outward copies are normalized to the source since 58b5bfd7f7 (`sdfg_to_tree.py:411-427`, `tests/schedule_tree/copy_direction_test.py`); a copy within one container whose memlet is written on the destination side (`[0:5] -> A[5:10]`, `_is_data_src=False`) kept its memlet un-normalized, so the tree read `A[5:10]` and wrote `A[0:5]` (and the round trip miscomputed); fixed by turning such memlets around (`sdfg_to_tree.py:419-426`). In a tree, `CopyNode.memlet` therefore always has `data` on the source side. |
| D54 | Private transients of a tree scope | Scope-lifetime transients are allocated per iteration (D39); trees have no access nodes | A transient is private to a map/consume scope when every mention of its name in the whole tree (memlets of code nodes, copy/view/reference targets and sources, dynamic inputs, data read by conditions, assignments and ranges) lies among the scope's children; its log entries are dropped per iteration/task. Views are transient, so per-iteration view bindings (`ViewNode`s first in the scope, D31) are private. |
| D55 | Views and references in trees | `ViewNode` carries the memlet normalized to the viewed container (`_make_view_node`); `RefSetNode.src_desc` is a descriptor or the code node that produces the pointer (`_prepare_schedule_tree_edges`, `tree_to_sdfg._set_reference`) | `ViewNode`: alias `target ↦ source` at the lower corner of `memlet.subset` (`aliasTo`, D31); a memlet not on `source` is `malformed`. `RefSetNode` from a data source: alias `target ↦ memlet.data` at the lower corner of `memlet.subset` (D32); from a code node: `malformed` (pointer-valued tasklet outputs are not modeled). |
| D56 | Pretty printing (`as_string`) | `as_string` prints memlets with `Memlet.__str__`, ranges with `Range.dim_to_string` (constant arithmetic simplified by SymPy, `0:N` for `0:N-1`), symbolic expressions with SymPy's `str` (numeric constants last: `M - 1`), code blocks verbatim, `LibraryCall` with the node's own properties and lambdas through `ast.unparse` | `STree.prettyPrint` reproduces this with a small polynomial normal form for additive expressions (`SymStr`: terms by decreasing degree, then by generator, constants last; products of sums are not expanded) and the kept source text of code blocks. Library-node properties: `LibraryCall.own_properties` (`treenodes.py:1015`) is the single source of `as_string`'s `k=v` list and is stored in the tree JSON as `[name, text]` pairs (`serialize.py:200`), because the node's serialized attributes omit default values and JSON objects lose the declaration order; the importer keeps them as text (`Json.lean:93`), for every library node. `other_subset` arrows run from the memlet's source to its destination: `data[subset]` is printed on its own side, decided by `is_data_src` (`Syntax.lean:534-553`); `Memlet._label` (`memlet.py:687-727`) does the same (`_is_data_src is False` → prefix, `None`/`True` → suffix, matching `src_subset`/`dst_subset`, `memlet.py:544-573`), so no Python change was needed. `CopyNode.as_string` prints `target[other_subset] = copy data[subset]`, which follows the data flow once the copy memlet is normalized (D53). Known gaps: a `CopyNode` with WCR prints `WcrOp.toLambda` instead of the original lambda text; a consume condition prints the parsed expression; union subsets follow `Memlet._label` structurally; dropped empty memlets (D57) are not printed (Python prints an empty entry). Identical on the whole corpus (including `matmul_lib`, a `MatMul` library node). |
| D57 | Memlet maps of code nodes | `TaskletNode.in_memlets`/`out_memlets` are dictionaries per connector; `LibraryCall` uses sets for nodes without connectors (`_state_schedule_tree`); empty memlets are dropped there | `MemletMap.dict`/`.set`; set-kind memlets are bound under the empty connector name (as `bindInputs` keys connector-less edges by `""`); a `Reduce` library node uses its single input/output memlet directly (`reduceData`, D37). Empty memlets (no `data`) of code nodes are accepted and dropped by the importer (`Json.lean:55-66`): in a sequential sibling list they carry no ordering beyond the list's own (owner decision, 2026-10-19; `sdfg_to_tree.py:345,494,519,523` already drops them for library nodes and data edges). A `CopyNode` with an empty memlet moves no data and is dropped as a whole (`Json.lean:117-121`) rather than kept as a no-op; `DynScopeCopyNode`, `ViewNode` and `RefSetNode` still require a memlet (they bind a value or an alias). Checked by `tests/STreeJsonTest.lean`. |
| D58 | Tree well-formedness | `validate_has_no_other_node_types` and `validate_children_and_parents_align` (`treenodes.py`), plus the structural expectations of `tree_to_sdfg` (chains, dynamic inputs, labels, gotos, break/continue) | `STree.check`: the Python validators hold by construction; additionally `elif`/`else` placement (D52), `DynScopeCopyNode` followed by a dataflow scope and `ConsumeScope` fed its `IN_stream` (D50), unique labels and resolvable goto targets (D51), `break`/`continue` inside a loop of the same dataflow scope, memlets and targets on declared containers (views are views, references are references, no WCR on streams, D6), code-node memlets on declared connectors, well-formed maps (`WF.checkMap`), distinct container/symbol names, and no assignment to a container. |
